<section><h2>A taxonomy, not a ranking</h2><table><thead><tr><th>Benchmark</th><th>Test object</th><th>Primary measurement</th></tr></thead><tbody><tr><td><strong>PhysCodeGym</strong> (2026)</td><td>156 reference videos, agents produce Blender simulation programs.</td><td>Visual, event, motion and native physical validity, including 43 counterfactual tasks.</td></tr><tr><td><strong>4DCodeBench</strong> (2026)</td><td>200 videos: 100 real-world and 100 synthetic. Agents write executable dynamic scene code.</td><td>Appearance, geometry and motion using flow, dynamic masks, trajectories and feature-space metrics, with mesh-quality checks.</td></tr><tr><td><strong>Physics-IQ</strong> (2025–26 benchmark)</td><td>Real experimental video scenarios used to assess generated-video physical realism.</td><td>Physically plausible video generation under varied conditions, rather than program-level native-state inspection.</td></tr></tbody></table><p>These are descriptions of different evaluation protocols. Numerical scores do not share a common scale and cannot be compared directly.</p></section> <section><h2>Where PhysCodeGym adds leverage</h2><p>4DCodeBench allows code that describes or prescribes trajectories. Its primary question is how accurately an executable graphics model reconstructs observed dynamics. PhysCodeGym more explicitly tests whether the motion is generated by declared physics mechanisms and whether those mechanisms survive changed conditions.</p><p>4DCodeBench is nevertheless important because it provides a mix of real and synthetic source videos and uses additional geometry/trajectory measurements. It also exposes the same bottleneck: motion is harder than static appearance.</p></section> <section><h2>The bridge that is still missing</h2><p>None of these benchmarks, by themselves, discovers a new physical law. Their outputs should feed an experimental loop that chooses conditions maximizing disagreement between candidate hypotheses, then measures the real outcome with calibrated sensors. A physically plausible reconstructed scene is an <em>experimental hypothesis</em>, not the experimentally verified mechanism.</p></section> <section><h2>Research sources</h2><p><a href="https://arxiv.org/abs/2610.03715">4DCodeBench paper (arXiv:2610.03715) ↗</a> · <a href="https://github.com/4DCodeBench/4DCodeBench">4DCodeBench repository ↗</a> · <a href="https://github.com/google-deepmind/physics-IQ-benchmark">Physics-IQ repository ↗</a>.</p></section>
