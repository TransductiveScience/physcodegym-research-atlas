Method 02 / Verification apparatus

How PhysCodeGym scores a physical world

Six metrics combine visual comparison with motion, events and executable scene inspection.

Six measurements, two aggregate families

ComponentWhat it examines
SSIMFrame-aligned structural similarity at 640 × 360.
LPIPSLearned perceptual similarity, reported as clipped 1 − LPIPS.
Object accuracyRubric checklist of required objects, model-judged across ballots.
EventsTemporal event rubric, scored via multiple multimodal-model ballots.
MotionSpatial and frequency-weighted motion-mask overlap.
Physical validityProgram and scene measurement, plus counterfactual trials when defined.

Visual = (SSIM + LPIPS + Objects) / 3
Physical = (Events + Motion + Validity) / 3
Overall = (Visual + Physical) / 2

Numerical evidence and evaluator uncertainty

The authors’ evaluation process prepares an unchanged submission in an isolated environment, runs a 240-frame native scene inspection, and freezes identities of the program and inputs. Judging requires supporting measurements and evidence ancestry, not merely a source-code assertion that a condition passed.

Parts of the verdict are still LLM-judged. Exact numerical witnesses should be distinguished from broad validity scores, and independent validation of the judge is a separate question. A third-party automated review has flagged this as an unresolved limitation, but that review is itself not an independent reproduction.

Reproduction checklist

The repository exposes task manifests, frozen rubrics, verifier tools, a dataset manifest, CLI commands, and tests. Reproduce by pinning the code revision, downloading the reference videos with documented checksums, installing the pinned Blender and Harbor dependencies, running a specific candidate, then examining the measurement bundle.

We have audited published descriptions and code layout, not executed a full benchmark reproduction.
