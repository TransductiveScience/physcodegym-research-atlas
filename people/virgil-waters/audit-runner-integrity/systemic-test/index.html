Finding / experiment completed

A systematic fault-injection test

The published VMS Institute audit contains 32 modules. The first uses Python assertions; the other 31 perform symbolic/numerical checks and accumulate their failures in a module-local counter. We inserted precisely one synthetic failed check into each of the 31 counter-based modules, in a fresh disposable copy. Their original mathematical calculations were left unchanged.

Every modified module subsequently reported a local FAIL. Nevertheless, the original, unmodified master runner reported 32 passing blocks, zero failed blocks, and exit code 0. This extends the earlier single-module test to every counter-based module. It establishes a failure-reporting defect, not the invalidity of the original calculations.

Method / explicit controls

What was changed and what was preserved

The official SymPy ZIP was downloaded and accepted only if its SHA-256 exactly matched the pinned original. Two fresh temporary directories were then used: one for the original and one for the all-module negative control.

After each module's total_steps = 0 initialization, the mutation adds one synthetic step to total_steps and one synthetic failure to fail_count. This preserves the accounting invariant that reported total steps equal reported passes plus reported failures. The other statements and mathematical tests remain unchanged. F0000 was not modified.

The experiment is deliberately artificial: it asks whether a failure that the module itself records is visible to the master audit. The test does not manufacture false mathematical evidence against a physical theory.

Global checks / prerequisites

A separate completeness defect

The common constants.py registry is empty in both runs. Its three cross-block identity checks are therefore skipped, yet Global: PASS remains displayed. No module in the downloaded package calls the shared constant-registration function. An honest machine report should distinguish an untested global identity from a successfully verified one.

Engineering response / drop-in independent layer

A strict machine verdict

The accompanying Python reproduction and strict-audit script parses the 31 internal check summaries and the F0000 assertion marker, verifies module completeness and counter arithmetic, checks the master report, and marks missing global prerequisite checks as incomplete. It returns FAIL for any reported failed subcheck, even if the author's master runner says PASS.

Reproducing the experiment requires Python and SymPy and executes the publisher's downloaded code after verifying the pinned SHA-256. Review external code and use a disposable VM if isolation is necessary. The script does not edit the preserved original archive or any private mathematical-break submission.

Limits / research ethics

What this result cannot prove

It does not prove that any of the 334 ordinary baseline checks failed. It does not evaluate every proposition in the VMS Mathematical Bridge, nor establish that the theoretical ontology is mathematically impossible. It demonstrates that the public audit's final PASS signal is insufficiently coupled to the error counters inside the verified modules, and that its global identity checks were not run.

The original single-module experiment includes an independently injected incorrect expected algebraic result, and an exception-control test. The present full-suite experiment confirms that the same reporting defect applies to all 31 counter-based modules.

Detailed, unreleased evidence concerning the Mathematical Bridge's differential-form claims is outside the scope of this page and remains private pending clarification of the institute's challenge rules.
